# 1. INTRODUCTION AND OBJECTIVES

## 1.1 Introduction

The Online Examination Management System (OEMS) is a web-based application designed to help educational institutions create, schedule and conduct examinations online. The system allows lecturers to create examination questions, manage assessments and view students' results, while students can securely access examinations, submit their answers and view their results where permitted.

This Software Configuration Management Plan (SCMP) establishes the procedures and guidelines for identifying, controlling, tracking and managing changes to the software components and documentation throughout the development of the OEMS. It provides a structured approach to managing project versions, reviewing modifications and ensuring that approved changes are properly tested before being incorporated into the system.

## 1.2 Purpose of the SCMP

The purpose of this plan is to ensure that all software components and project documents are properly managed throughout the development lifecycle. It defines how configuration items will be identified, how changes will be controlled, how different versions will be maintained and how completed changes will be reviewed and approved.

The plan also provides a common framework that enables team members to collaborate effectively while reducing errors, unauthorized modifications and inconsistencies in the project.

## 1.3 Scope

This plan applies to the development and maintenance activities of the Online Examination Management System. It covers the management of source code, database scripts, requirements documents, test cases, technical documentation and configuration files.

It also addresses version control, change management, testing, release management, configuration audits, backup procedures and the use of supporting development tools.

## 1.4 Software Configuration Management Objectives

The main objectives of software configuration management for the OEMS project are to:

1. Maintain consistent and identifiable versions of all project components.
2. Prevent unauthorized modifications to source code and other configuration items.
3. Track changes and development activities throughout the project.
4. Establish a controlled process for requesting, reviewing and approving changes.
5. Ensure that software modifications are tested before they are released.
6. Improve collaboration and coordination among project team members.
7. Maintain accurate project records and documentation.
8. Ensure that approved software versions can be identified and recovered when necessary.
